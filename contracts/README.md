# Dotify contracts

The fresh-generation candidate registers artist-controlled releases without
minting or transferring NFTs. `ArtistDirectory` maps the original artist to
its `SmartRuntime`; the bound artist controls publication and release policy,
and the accepted technical administrator controls Diamond upgrades.

The shared pallets cover registration/metadata, access, royalties and
contributions, alongside the core Diamond routing and administration pallets.
Listeners use Free, Classic paid access or verified personhood according to the
release policy. Token possession grants no access. Royalties and pending claims
retain their own beneficiary rules.

See the [contract API](../docs/reference/contracts-api.md),
[administration model](../docs/reference/runtime-artist-authority.md) and
[exact price and NFT-free model](../docs/reference/native-price-without-nft.md).

## Local checks

```sh
cd contracts/evm
npm ci
npm test
npm run generate:abis
```

Generated Web and API bindings must match compiler artifacts. Product CDM
bindings and candidate metadata are generated by `npm --prefix web run
generate:cdm` and `npm --prefix web run generate:cdm-metadata` from the repository
root. Generation does not publish a CDM package or metadata blob.

## Fresh generation deployment configuration

`DOTIFY_NATIVE_TOKEN_DECIMALS` must explicitly name the verified native Balance
precision, from 0 to 18. This differs from EVM `msg.value`'s 18 decimals. For a
verified 10-decimal native chain, the smallest Classic price is `100000000` EVM
units, or `0.0000000001` native tokens. The deployment scripts refuse an absent
or malformed value; the runtime enforces the declared precision and the Product
writer compares it with its connected native configuration.

The selected testnet delivery requires matched contracts, API and clients after
remaining audit and target Revive/physical Host acceptance. Follow the
[deployment gate](../docs/operations/deployment-configuration.md#native-price-and-nft-removal-493)
before using any signing/deployment command. No prior contract, release, claim
or key domain is migrated by this source change.

`createRuntime()` creates a shell owned by the factory. Seven subsequent
`installRuntimeStep()` calls install the remaining facets and atomically finish
artist-bound readiness, administration and directory membership. There is no
NFT installation step. Local EVM success does not establish native weight limits.

Metadata correction is installed by default before finalization. Follow the
[fresh-generation procedure](../docs/how-to/prepare-fresh-testnet-generation.md)
for the public-address-only plan and exact source/CDM readback.

`deployments.json` still identifies the earlier deployment until an authorized
fresh rollout replaces it. `contracts/evm/cdm.json` is a finalized historical CDM
snapshot used to preserve those recorded package versions; its old embedded ABI
is not the candidate runtime API. Do not publish newly generated ABIs against
those old addresses or treat them as evidence of a deployed NFT-free generation.
