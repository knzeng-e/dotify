## Result and decisions

W01 adds a dedicated `Dev Quality Gates` workflow for pull requests targeting
`dev`, pushes to `dev`, and manual runs. The workflow has no path filters, so a
documentation-only PR still receives the same stable check set and cannot be
blocked by a skipped required workflow.

The existing `main` / `master` workflows remain intact. W01 uses a new workflow
instead of broad rewrites to keep historical main coverage unchanged while
making `dev` independently enforceable. Fork PRs do not need secrets because
the workflow uses ordinary `pull_request`, read-only contents permission, local
services, local fixtures, and no deployment steps.

Branch protection is documented in `docs/operations/dev-quality-gates.md` but
not applied, because repository administration is outside this sequence.
