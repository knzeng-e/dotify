## Result and decisions

The artist workspace now starts with the musician's next useful action. New
artists see one first-release action instead of three empty metrics and several
competing publish controls. Mobile tabs retain horizontal navigation and now
show a visible scroll affordance. Desktop keeps all five destinations available
without adding dashboard density.

Onboarding no longer invents `Dotify Artist`, a generated handle, or a verified
badge. It asks for a blank artist name, introduces the three steps before the
decision, explains shared-listening consent where it is given, and tells the
artist exactly why creation is unavailable. The custom checkbox preserves
keyboard focus and native checked semantics.

The release flow uses Music, Details, Listening, and Review. Access choices are
described as free, free with human verification, or direct support. The final
review states listening access, total support, the fee boundary, publication
boundary, and value flow once. When no collaborator is configured it says
`You receive 100%`. Runtime, address, IPFS, archive, and proof references remain
available in collapsed technical disclosures and the Advanced tab.

Publication semantics did not change. A submitted approval is still incomplete
until Dotify reads the matching release from the catalog. Upload, encryption,
contract, split-validation, and consent behavior are unchanged. Upload status
copy now describes secure saving without exposing the IPFS implementation in
the primary flow.
