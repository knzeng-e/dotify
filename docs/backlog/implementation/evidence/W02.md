## Result and decisions

W02 replaces public upload endpoints with an artist capability flow. The web
and Product identity adapters first open an existing EIP-191 or Product
sr25519 session. The API resolves `ArtistDirectory.runtimeOf(requester)` and
only an address with a runtime can obtain a short-lived, single-use capability.
That capability is signed with a purpose-specific HKDF key and binds the
requester, chain, audio/cover/metadata purpose, maximum bytes, expiry, process
epoch, and unique ID.

The API reserves per-artist and global capacity when it issues the capability.
It enforces outstanding-grant concurrency and rolling completed-byte quotas,
detects supported media from received container bytes instead of browser MIME,
checks audio content identity, and releases reservations on validation,
storage, or interruption failure. Pinata requests now receive the inbound
abort signal. Manifest objects are strict at every nested boundary.

Session and upload tokens include a random process epoch. Dotify's tracked Fly
topology is restricted to one API machine. Logout revocation remains effective
during that process; after a restart every earlier session and upload token is
rejected, so a logged-out token cannot become valid again. This deliberately
chooses safe restart invalidation over a new persistent datastore migration.
Horizontal scaling remains unsupported until quota and revocation state share
a transactional store.

Free listening and guest room entry are unchanged and remain unauthenticated.
No contracts, keys, stored ciphertext, or pinned manifests are migrated.

## Compatibility and operations

- Supported devices, browsers, and Product host versions: unit/build coverage
  includes both EVM and Product sr25519 identity adapters; Playwright uses
  desktop Chromium. No real Product host/device version was exercised.
- New config/permissions and documented defaults: upload TTL, rolling quota,
  byte limits, and concurrency limits are documented in
  `services/api/.env.example`, the environment reference, and the deployment
  runbook. `services/api/fly.toml` sets `max_machines_running = 1`.
- Storage/key/contract migration and compatibility evidence: none required.
  Capability and session HMAC keys are independently derived from the existing
  backend-only `CONTENT_KEY_MASTER_SECRET`; no frontend secret was added.
- Deployment identifiers: none; deployment was not authorized or run.
- Rollback procedure and rehearsal evidence: revert the W02 commits and deploy
  API and frontend together. Rolling back only one side intentionally leaves
  artist uploads fail-closed because old clients cannot satisfy protected API
  routes and new clients cannot authorize against an old API. Rehearsal not
  run.
- Data collected, retention, and user controls: process-local capability IDs,
  address-scoped byte usage, and revoked session IDs live only until expiry or
  restart. Tokens, signatures, keys, and uploaded contents are not logged.
