## Result and decisions

[ADR 0036](../../../adr/0036-bounded-catalog-indexing.md) describes the bounds,
checkpoint authority, content/progress split and rollback. The common budget
covers nested RPCs, not just outer artist jobs. Directory pages retain the
existing view; track hashes and releases run in bounded work batches without
assuming a deployed Multicall contract. W38 retains actual contract pagination
and payload/split limits; W37 does not silently truncate existing rights data.

Each complete block range commits before the next starts; reconciliation cannot
jump past failed event replay. Reads use the selected confirmed block, and
checkpoint hashes are checked during indexing. Intermediate catch-up remains
explicitly stale across replicas/restarts. Canonical freshness and the existing
on-chain checks remain mandatory for content keys. Guests, contracts and access
policies are unchanged.

Separate compact progress from content avoids rewriting all artists/releases
on idle polls while retaining restart position and freshness. Both storage
adapters retain schema-1 base snapshots; old bases work without progress. Shared
content/progress updates are transactional and retain W36 connection fencing.
Concurrent HTTP reads cannot mix an old header with newer arrays. No failed
write, including local-mode writes, advances the in-memory checkpoint.

Content revision and ID/hash/runtime/artist indexes are memoized on immutable
content arrays. Public hash-only detail keeps all claims and rejects ambiguity;
key requests retain their full runtime/hash identity. Empty runtimes skip
periodic track-count reads after discovery, but their first registration event
still creates the release. Reorg/forced rebuild clears that optimization.

## Compatibility and operations

- Web/Product both consume unchanged catalog routes; no client permission or
  SDK change. Physical Host checks not run in this backend-only sequence.
- New non-secret API defaults: read concurrency 8 (1-32), log block range 1000
  (1-10,000), runtime address batch 100 (1-1000). See `.env.example` and
  [deployment configuration](../../../operations/deployment-configuration.md).
- Local storage: base JSON plus `.checkpoint`; back up both. PostgreSQL uses the
  existing table/namespace plus `catalog-checkpoint-v1`; no SQL migration.
- Progress is bound to base content revision and checkpoint identity. Missing
  or mismatched progress replays from the base; corrupt progress fails explicitly.
- Rollback to a pre-W37 API ignores compact progress. Quiesce the writer and
  force reindex with the rollback binary before reopening keys. W36 shared
  auth/custody migration and restore rules remain mandatory.
- No keys, receipts, encryption nonce reservations, upload jobs or private
  participant data are added/changed. Catalog data is already public.
- Deployment IDs: none. Last published Product remains 0.1.62; activation of W36
  and combined client/API acceptance are still separate operational gates.
