## Result and decisions

The first Music screen no longer presents a selected release or player dock before the listener chooses music. The catalog keeps its internal default track for existing room-creation behavior, but `trackInfo` is now the visual boundary for explicit listening intent. Rendering discovery still performs no audio fetch, key request, signature, payment, or access mutation.

Catalog and artist-release cards show one compact cue derived from the same release policy consumed by the player: `Free`, `Verified humans`, a native amount such as `0.5 PAS`, or `Unavailable`. The full access state is included in the actions' accessible names. Opening the release continues through the authoritative access check and complete support terms.

Generated artwork contains no title or artist text. Remote cover pixels remain hidden until the load event. After the existing 1,200 ms W08 budget, a slow cover keeps loading behind the text-free deterministic fallback and replaces it when the request completes; only exhausted gateways make the fallback the image source. Display-only whitespace is normalized at catalog ingestion without changing hashes, addresses, IDs, or policy values.

The artist profile now names its primary action `Listen to latest release`, hides release actions when none exist, and does not repeat the artist name inside every release card. The release-derived public catalog inherently omits zero-release directory entries, so it does not surface a raw controller address as an artist name.

During the complete browser run, the keyboard canvas regression exposed that transitioning the `background` shorthand could briefly interpolate the body's base color below full opacity. The base canvas is now a permanent opaque layer while only aura images transition. This preserves the visual effect and removes the transient flash state.
