# Playback, discovery and room entry stability - 2026-10-17

## Scope and diagnosis

Owner feedback follows Product 0.1.53. Base: tested `dev`
`e3325f9a6dfda7ff14d7029d60b4550354736c73`. Refs #88, #274, #250 and #288;
this is a stabilization slice, not completion of W33's regional edge rollout or
W35's adaptive/gapless player. Production remains on 0.1.53 until a separate
reviewed deployment.

The supplied console captures show public Pinata/IPFS failures and CORS refusal,
followed by DAV2 full-file recovery. Source inspection found that range delivery
has only Pinata readers, transient Nearby renewal failures immediately revoke a
still-valid announcement, and asynchronous artwork enrichment drops a room when
capture metadata replaces the track object. Canonical runtime enrichment also
makes repeated captures look like a new song to the chat announcement check.

## Changes and boundaries

- `services/api/src/services/encryptedMedia.ts` and `routes/media.ts`: process-local
  read-through for active registered encrypted CIDs. Range and full-object reads
  share bounded ciphertext caches and coalesced requests. Fixed public readers,
  a strict redirect allowlist, byte/time/concurrency caps and catalog eligibility
  checks prevent an arbitrary URL proxy. No keys, clear audio or credentials are
  handled. DAV2 authentication remains client-side after normal access checking.
  This reduces browser CORS dependence; it cannot repair missing IPFS content.
- `web/src/services/pinata.ts`: the existing API URL supplies the first audio reader;
  direct readers remain fallbacks, including when an older API returns 404.
  Unsupported MSE formats take the normal complete-file compatibility path.
- `nearbySession.ts`: a transient refresh failure leaves the existing lease and
  result deadlines intact and retries a fresh location. No expiry extension or
  stale-coordinate republication is permitted. Explicit opt-out, denial,
  backgrounding and disconnect still withdraw presence.
- `server/room-track.mjs`: semantic release comparison distinguishes capture
  updates from actual track changes. Discovery tolerates metadata refreshes while
  in-flight, and chat ignores recaptures/null recovery for the same release.
- Join UI asks for a name or nickname, hides default placeholder identities and
  omits the repeated room code after selection. Radar covers are smaller, the
  beam crosses cover planets, details stay above the beam and the redundant
  Open invitations heading is removed. App-authored long dashes are removed from
  messages, title and labels; older wire formats and artist-authored text retain
  their data format. Existing request text remains resolvable.
  Queue/request panels also have distinct React keys; the first CI exposed their
  pre-existing collision during a mobile tip test.

The operating limits, deployment order and rollback are recorded in
`docs/operations/deployment-configuration.md`. No Redis, paid gateway, new
credential, permission or contract migration is introduced. Full W33 still
requires provider selection, regional measurements, pre-warming and pilot load
evidence. Native Product location and background audio remain physical Host gates.

## Validation

- 992 frontend unit tests, 116 signaling tests and 187 API tests passed.
  Focused cases cover lease-preserving transient failure, deadline expiry,
  permission revocation, actual track changes, duplicate chat announcements,
  malformed/oversized ciphertext, range validation, request coalescing,
  cold-download concurrency and refused URLs/redirects.
- 28 real-media continuity scenarios passed in Chromium and WebKit, including
  the API relay with public readers unavailable, source swaps preserving the
  clock, pause during recovery, key denial and terminal authentication failure.
  These use synthetic encrypted tones and fixture routes, not live media claims.
- 15 real-socket browser room creation/join/arrival scenarios passed. Chosen-room
  entry checks a single nickname field with no repeated code on mobile/desktop.
- Web and frozen Product builds passed. ESLint reports no errors and the two
  existing App.tsx dependency warnings; existing large-chunk warnings remain.
- Six Nearby Web and three Product fixture scenarios passed; final CI is recorded
  in the PR.
  An initial Nearby assertion still expected the former long dash in distance
  text; it was aligned with the requested visible copy and rerun.
- Mobile/desktop radar screenshots were visually inspected; synthetic covers
  do not prove availability of an artist's original IPFS cover.
- The first full CI browser run passed 239/240 cases; the mobile tip case timed
  out during context cleanup. It passed alone and nine concurrent repeated cases
  passed locally. The duplicate panel-key warning in that log was corrected and
  guarded in room workspace tests. Final candidate CI remains a release gate.
