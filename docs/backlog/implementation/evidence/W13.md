## Result and decisions

W13 adds a concrete release gate instead of a checklist-only pilot plan. The new
`npm run smoke:pilot-release` command reconciles:

- W01-W12 dependency evidence against the current candidate;
- Product DevNet static gates from the existing journey harness;
- W13 issue/backlog mapping;
- the reversible pilot release plan;
- Product DevNet contract inventory;
- optional Product CDM host smoke, Product room smoke, and aggregate pilot
  evidence.

The command exits non-zero for unsafe local release state, but it does not fail
merely because live host or pilot evidence is absent. Missing live evidence is
reported as `blocked` or `not-run`, so Dotify cannot accidentally infer a shipped
Product/pilot claim from a static web build.

The original release package kept the tracked Product app on `dotify-test01.dot`,
Product executable `[0, 1, 18]`, viem runtime writes by default, exact API/signal
origin allowlists, empty browser secrets, and dormant Statement Store room
beacons. No contract migration, deployment, key rotation, participant contact,
or access-control change was performed.
