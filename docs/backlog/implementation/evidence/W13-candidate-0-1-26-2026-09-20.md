## Result and decisions

The candidate closes three release-preparation gaps before asking a person to
exercise the Product host:

1. The manual GitHub workflow now checks out an explicit full SHA and builds it
   with no signer, mnemonic, upload, or Product write. GitHub Actions cannot
   publish `dotify-test01.dot`.
2. DotNS publication remains local. The deploy CLI reads `MNEMONIC` from the
   ephemeral child-process environment instead of expanding it into process
   arguments. A static release gate rejects a future `--mnemonic` regression.
   Validation and release profiles remain distinct bundles.
3. Server-side cover processing moves from `sharp 0.34.5` to `0.35.4` after npm
   reported High-severity libvips vulnerabilities. The complete API suite and
   responsive-cover tests pass, and the follow-up audit reports zero known
   vulnerabilities.

The validated and published Product bundles now share one frozen build command.
It consumes the reviewed, committed catalogue snapshot without contacting the
mutable live catalogue API. A static gate rejects publication commands that
reintroduce a live refresh, closing the review finding that CI and local
publication could otherwise compile different catalogue contents.

The Product catalog bootstrap was refreshed from the live ten-release catalog.
The W04/W05 sequence-to-issue mapping now matches backlog.json: W04 is #143 and
W05 is #145.

## Security, compatibility, and operations

- No mnemonic, wallet address, signature, key, media reference, participant
  identity, or precise device identifier is stored in this evidence.
- The workflow grants only `contents: read` and receives no deployment
  authority. GitHub Actions can build and validate but cannot publish.
- The owner phrase remains local, is not written to disk, and is not expanded
  into process arguments. The transient named pipe was removed immediately
  after the deploy process consumed it.
- The API dependency update changes no route, schema, contract, key format, or
  persistent state. Reverting the package and lockfile restores the prior
  native image dependency, although doing so would restore the audit findings.
- The currently published `[0, 1, 25]` CID remains the rollback target. It was
  not republished in this sequence, so rollback is verified as documented but
  not rehearsed.
- The headless Product Web probe still reproduces the documented Smoldot crash;
  it is not counted as a supported interactive-browser failure.
