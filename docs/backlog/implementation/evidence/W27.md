### Final responsibility decision

| Responsibility | W27 decision | Evidence boundary |
| --- | --- | --- |
| Expiring public room discovery | **Hybrid** | Keep the existing opt-in Celerity beacon as a hint; validate joinability and occupancy through Socket.IO. |
| Coarse room presence | **Hybrid observation only** | Live samples, one duplicate and partial windows prove useful diagnostics but not an authenticated or complete count. Never fabricate occupancy from statements. |
| Reactions | **Retain Socket.IO authority** | Encrypted Product mirroring is viable, but the baseline is asymmetric and best-effort loss is not an equivalent visible-delivery contract. |
| Short in-room chat | **Retain Socket.IO authority/history** | Foreground exchange works; background/expiry deliberately loses the Celerity mirror while canonical chat recovers. Keep the encrypted mirror opt-in for measurement only. |
| Track requests and queue decisions | **Retain Socket.IO** | Proposals crossed both directions in baseline, but host acknowledgement, removal and full snapshot recovery still require the canonical service. |
| Player snapshots, lineup and roles | **Retain Socket.IO** | Host authority, monotonic reconciliation, atomic admission and resume ownership were not moved or weakened. |
| SDP/ICE rendezvous | **Retain Socket.IO** | Offline encoding shows account-budget pressure; no live mobile SDP, glare or retry equivalence exists. |
| Audio, protected source URLs and content keys | **Never Celerity** | WebRTC/TURN remains media transport; entitlement and key release remain fail-closed on their existing owners. |
| Product Host ChatManager invitations/actions | **Not activated** | API feasibility exists, but consent, scheduling, provenance and real delivery are outside this sequence. |

The W27 implementation and live comparison are therefore reviewable, but the
comparison rejects any authority migration in this PR. Tracked defaults remain
off. A later change may reconsider one low-risk event class only with a larger
sample, equivalent guest behavior, explicit operational telemetry and the W13
release boundary reviewed. No contract, payment policy, catalog, entitlement,
key-delivery or media responsibility moves to Celerity.

instead of waiting forever. WebRTC peer ownership and all access checks remain
in their existing modules.

`VITE_DOTIFY_ROOM_REALTIME=observe` subscribes in a Product container while a
room is joined. `dual` also publishes host aggregate presence every 10 seconds
with a 30-second TTL. Neither mode applies Celerity data to visible room state.
Guests never publish or request an account to join. SDK Host mode uses the
sponsored allowance; its signature is not Dotify host authentication.

The strict schema refuses private and unsupported payloads. Room/channel,
versions, IDs, sequences and both expiries are checked before bounded replay
tracking. SDK encoding enforces byte size; local reservations leave room for
one discovery beacon and survive uncertain submits until expiry. Other tabs
and allowance consumers remain outside this local budget view.

The observer is isolated from the room port and state setters. Initialization,
subscription and publication failure cannot stop audio or grant authority.
It disposes late clients, stops on an 8-second deadline or interruption, never
overlaps an uncertain write, and records publisher self-echo separately.
An already-issued Host operation cannot be canceled by this timeout.

The [per-event decision matrix](../../../explanation/room-realtime-transports.md)
retains Socket.IO for all authoritative responsibilities. Existing beacon
discovery is hybrid. No private chat or signaling is published; encryption is
therefore not installed as an unused production key system. The offline
experiment exercises ephemeral X25519/AES-GCM/deflate fragmentation with real
SDK encoding, and explicitly lacks authenticated peer key agreement.

to actions. Invitations and Join buttons are future Host-surface candidates;
scheduling, consent and real delivery are unverified. No messages are sent.
