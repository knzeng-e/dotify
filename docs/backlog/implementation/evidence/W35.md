## Result and decisions

[The design](../../../explanation/continuous-listening.md) explains media
ownership, cancellation, authorization, optional capabilities and local storage.
One silent authorized successor is prepared near the end and the exact native
node is adopted. No crossfade, early cut or room transport change is introduced.
The prepared lease is bounded and the existing source remains usable when
speculation fails. A natural ended sequence differs from a deliberate pause:
its native pause/timeupdate events must not discard the ready successor.

Adaptive delivery starts at 96 kb/s and selects authenticated renditions from
network throughput and buffer headroom. Media Session uses explicit idempotent
commands; a system Pause also cancels autoplay intent during preparation.
The local resume offer restores only current active catalog identities through
normal access checks, never a saved source or room membership. It is scoped to
the local account/network, expires in seven days, and has explicit removal.
An initial catalog selection is not a new listening intent.

Alternating prepared native players were chosen over concatenating unrelated
MSE timelines across catalog identity, gain and room-capture lifetimes. This
keeps access and room ownership explicit. Native handoff timing is measured,
but sample-accurate, inaudible boundaries on real albums/mixes and background
execution on physical Hosts are not established by browser event timestamps.
Unsupported AAC MSE retains explicit-play compatibility, without speculative
whole-track downloads.

## Operations and acceptance

PR review [r4385083381](https://github.com/knzeng-e/dotify/pull/338#discussion_r4385083381)
identified an authorization bypass for non-encrypted policy-managed candidates.
The regression first reproduced unauthorized playback and a skipped access
read on the reviewed source. Such sources are now excluded from speculative
loading/adoption and always repeat the runtime access check on selection;
readiness cannot stand in for authorization. Six additional scenarios run
in both Chromium and WebKit: denied Classic, denied personhood, allowed Classic,
unavailable runtime and a ready local candidate acquiring an artist policy,
with or without a changed encryption classification. Prepared identity also
binds source classification, encryption, artist and local URL so an old local
player cannot impersonate a newly encrypted release. All 44 encrypted/local
continuity scenarios pass together across both engines (22 per engine). This changes no permission, API, key or runtime format.

No new environment variable, Host permission, backend route, production
persistence schema, contract, secret, dependency or deployment is introduced.
W34's existing routes remain prerequisites; absence of a prepared grant takes
the cold path without a speculative signature. In-memory ciphertext is bounded
and decrypted/source/key material is not persisted. A browser checkpoint holds
local public account/network scope and bounded release/queue/position facts,
not a server-side listening history. Storage denial does not block playback.

Client rollback ignores the new versioned checkpoint; preserve existing server
custody, receipts, sessions and nonce reservations. The first-sound schema-6
export adds optional identifier-free host/solo continuity aggregates, excludes
native paused/startup time and guest transport, and keeps human confirmation distinct from native `playing`. See the
[deployment checklist](../../../operations/deployment-configuration.md).
