## Result and decisions

[ADR 0035](../../../adr/0035-shared-api-trust-state.md) chooses PostgreSQL for
atomic expiring nonces, shared family revocations, upload budgets/capabilities
and one elected catalog checkpoint writer. Nonce capacity is bounded; expiry
is checked after contention, using database time. Database failures do not
fall back to local identity/quota state. Sessions have an independent secret,
last two hours and renew on connected-wallet use within the final 15 minutes,
with an original 24-hour sign-in ceiling. Logout also revokes renewed siblings
when supplied with an expired parent within that ceiling.

The W36 audit predates durable encrypted publication jobs. Copying their local
volume into two writers would split permanent AES nonce custody. Instead, two
public edges share trust/catalog state and forward publication/job/history
requests to one authenticated private custody service. The edge streams raw
multipart; it does not inherit the local multipart parser. The private service
preserves the existing owned queue, nonce ledger and verified receipts. A
single-writer database lock plus heartbeat blocks duplicate custody startup
and closes admission/aborts encoding on connection loss. This does not authorize
active copies of the owned volume or claim publication high availability.

Content-key derivation, chain access policy, contract state, anonymous room
entry and signaling are unchanged. W37 retains catalog batching/lookup work;
W39 retains horizontal rooms. Public catalog reads use the committed checkpoint
on every replica; explicit stale public data is allowed during an outage and
never serves as content-key authority.

Upload accounting is initialized only by the offline namespace migration. A
missing or malformed upload document fails closed rather than starting an empty
budget. The integration suite verifies both failure cases.

## Compatibility and operations

- Web and Product use the same connected-wallet session boundary. Anonymous
  listeners and speculative next-track preparation do not renew or prompt wallets.
- Defaults remain an explicit single-node `local`/`combined` development mode;
  local session auth now also needs a dedicated `SESSION_SECRET`.
- Shared startup requires a matching initialized namespace, stable epoch,
  independent signing secret, explicit edge/custody role and private service
  authentication. Edge refuses encoder settings. Nothing initializes lost
  trust/nonce custody at startup.
- [Deployment configuration](../../../operations/deployment-configuration.md)
  links the mandatory [migration and rotation runbook](../../../operations/shared-api-state.md).
  The public Fly profile has a two-machine ceiling; the separate private profile
  retains one authoritative owned volume and no public HTTP service.
- Initial import requires a quiesced old API, final catalog/revocations, a drained
  in-memory quota window and verified transfer of the full owned volume.
  Existing old session signatures require explicit bounded overlap, never an
  automatic content-master fallback. Content-key version secrets stay unchanged.
- Normal application rollback keeps the same PostgreSQL namespace/epoch, valid
  signing overlap and custody volume, with one public edge if needed. A stale
  backup requires security-write reconciliation or explicit epoch invalidation.
  Returning to the old local-state binary after shared writes is unsafe.
- Data: short-lived wallet nonces, family IDs/expiry, address-bound upload
  budgets and public catalog. Lazy expiry cleanup and backup retention are
  documented; no content secret, content key or bearer credential is stored in
  the shared tables. Existing private receipt/job retention is unchanged.
- Deployment IDs: none. Last published Product remains 0.1.62; W35 and W36 are
  part of a future combined test deployment, not installed evidence.
