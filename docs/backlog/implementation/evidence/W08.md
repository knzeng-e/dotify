## Result and decisions

W08 ships a bounded first-sound observability and recovery slice on top of the
existing DAV2 startup hardening already present on `dev`.

The app now installs `window.__DOTIFY_AUDIO_STARTUP__` for QA. The snapshot keeps
bounded DAV2 startup events and host source-to-first-audio events in memory, so
reviewers can inspect key authorization, gateway selection, first bytes,
decryption, MSE append, fallback/error, and actual media start without reading
console logs. The snapshot stores timings, refs, CIDs, gateway URLs, and phase
metadata only; it does not expose content keys or decrypted media.

The catalog hook now maps DAV2 phases to short player/dock labels while audio is
preparing: access confirmation, gateway lookup, first bytes, first sound prep,
fallback, and unavailable states. Unauthorized access still fails closed to the
access gate with no preview source and no listener key request.

Cover artwork now uses a shared fallback generator and a 1.2 second per-gateway
budget. If gateway sources fail or time out, the UI renders deterministic Dotify
artwork seeded by the track/release title instead of leaving broken image
surfaces. This treats cover work as a linked #87 slice without claiming the whole
responsive cover pipeline is complete.

No backend read-through gateway, CDN purchase, playback-engine rewrite, preview
system, contract change, or production secret change was introduced.
