## Result and decisions

W04 keeps the current runtime semantics and fixes the product promise around
Classic access. A Classic payment is now described as an on-chain paid-access
record with no fixed expiry in the current runtime, not a perpetual media
availability guarantee. Full playback opens only when the payment transaction is
included and a fresh runtime read-back confirms both `musicAccHasPaid` and
`musicAccCanAccess` for the listener address.

The implementation also makes inactive releases fail closed in the browser,
updates Classic support receipts with amount, conditions, and recipient
disclosure, and removes wording that implied NFT ownership, SmartRuntime
ownership, artist policy control, and royalty beneficiaries were the same right.
Those facts are now documented and tested separately.

No retroactive rights migration, contract upgrade, or legal entitlement model was
introduced. Solidity behavior is unchanged except for tests and comments that
document the current boundary.
