## Result and decisions

Rooms gains a Nearby list, and the host's People panel gains Visible nearby.
Both require explicit action. Active settings collapse so the matching track,
host and Join button lead the mobile view. Device permission denial/unavailable
containers offer offline city-centre selection, alongside existing links/QR.
Selecting a radius never starts collection. Search and publication are separate.

The v2 contract replaces inert v1 assumptions: one coarse spherical-grid cell,
5/10/25 km radii, no automatic sparse-area expansion, no cell IDs in replies,
and strict 90-second leases. The proposed 2 km preset is withheld because each
cell is approximately 2.22 km across. Distance between cell centres must fit
both selected radii. Exact circles cannot be guaranteed: cells and permitted
fix error introduce several kilometres of boundary uncertainty. Nothing proves
physical presence or changes room access rules.

The current room-host socket authorizes publication; room display metadata is
derived server-side. The server never accepts a wallet, room ID or track metadata
in publication. Separate memory maps hold presence and short-lived rate budgets.
No Redis/archive/new endpoint is needed for this single-process implementation.
Search replies contain only public room identity/display fields, bucketed
presence, capacity and relative lease. The number of cards still discloses up to
20 matching rooms; buckets do not provide k-anonymity. Public room IDs and names
remain linkable even when discovery IDs rotate.

Client cancellation/revision guards prevent late fixes or acknowledgements
from reactivating consent. Backgrounding, permission revocation, disconnect and
room closure stop collection/refresh and clear state. Resume requires explicit
action and fresh permission state. Offline opt-out clears locally immediately
and explains the possible 90-second remote expiry. Relative leases subtract the
request round trip, tolerating device/server clock skew.

Manual selection currently covers 12 named city centres; arbitrary locality
search is not implemented. Report hides locally and counts an aggregate safety
signal, explicitly not a moderation case. These limits must be considered before
public enablement. Native Product location is deliberately unsupported until
physical capability evidence exists; no Product permissions were added.

## Compatibility and operations

- Flags: exact `VITE_DOTIFY_NEARBY=on` and `SIGNAL_NEARBY=on`; unset/off disables.
- Host authority and guest media/key boundaries are unchanged. No contracts,
  catalog, content keys, secrets or storage migrations.
- Standalone secure browser location requires Geolocation and Permissions APIs.
  Native/embedded Product containers offer manual areas; actual versions remain
  untested. Manual lookup has no external geocoder.
- Presence: 90 seconds, refreshed every 30 seconds while foreground/consented.
  Device watches return one coarse cell and are cleared; precise fixes are not
  retained. Disconnect/room end revoke immediately. Restart empties memory.
- Rate budgets: 6 searches / 12 publications / 3 reports per minute, per socket
  and HMAC network key. Shared NAT crowds share the network budget. Revocation
  is unthrottled. Multiple networks/spoofed fixes remain residual risks.
- Scaling: single worker only. Multiple workers need shared TTL presence,
  coordinated budgets and partition/revocation tests before enablement.
- Rollback: disable server flag and restart (ends rooms), then rebuild frontend
  off. Frontend-only rollback leaves at most the 90-second remote lease. Local
  off/restart behaviour verified; no live rollback performed.
- Full settings: [deployment configuration](../../../operations/deployment-configuration.md),
  [protocol](../../../reference/socket-events.md),
  [privacy contract](../../../design/dotify-nearby-discovery-privacy.md).
