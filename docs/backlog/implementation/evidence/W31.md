## Result and decisions

1. **Worldwide reconnect.** Already fixed in the merged #283 (the list restarts from `disconnected` once the cooldown ends); verified, not reimplemented. W31 adds worldwide wording: the list now says "Reconnecting to live rooms…" or "Live rooms could not refresh" instead of the shared session's Nearby messages.
2. **No refresh flicker.** Background 30-second refreshes keep the current phase; only an explicit start shows `locating` or `checking`.
3. **Hide and Report on worldwide cards** through a new shared `DiscoveryRoomList`, which also replaces the duplicated Nearby list markup.
4. **One discovery choice.** "Who can find this room?" with Link only (link icon), Nearby (radar), Everyone (globe), as a radio group in the creation sheet and the room panel. The two mutually exclusive switches and their styles are removed. Everyone states that the host name and track become visible to anyone on Dotify. Each radio is named by its label only, with the hint as its description.
5. **Truthful messages.** Revocation names the withdrawn mode ("no longer visible worldwide" or "nearby"). A failed host attempt warns that the previous publication may remain discoverable for up to 90 seconds until the server acknowledges revocation. Only then does it confirm link-only availability. A device that only returns coarse fixes ends with the existing "too uncertain" message and shows "Waiting for a more precise location…" after the first coarse fix. The listener empty state reads "No open rooms within about N km yet. Widen the search, or open a room here." with an Open a room here action.
6. **Lighter first load.** `ArtistShell` is lazy-loaded. Measured on the same build: main chunk 1,312.54 kB before, 1,221.67 kB after; the studio is a separate 93.14 kB chunk. The artist console hook still loads eagerly because the providers use it.
7. **Hygiene.** `useId` for the worldwide title; the 42 km maximum is derived from `NEARBY_RADII`.
