## Result and decisions

Dotify now has one documented Night Console visual contract for typography,
semantic color, links, live state, icon scale, focus, controls and global
layers. The CSS keeps 16 existing sheets and introduces no dependency or
framework. Component sheets consume the shared roles in
`web/src/styles/tokens.css`; superseded checkbox, live-dot and root-token
overrides were removed rather than covered by another override sheet.

The eight-step type scale has a 12 CSS px minimum. Instrument Sans remains the
interface voice, while Newsreader is reserved for narrative page, artist,
release and immersive-player headings. Cross-platform symbol fallbacks keep
artist names such as `Lord Ékomy Ndong ☥` visible in Chromium and WebKit.
Monospace remains limited to aligned or exact values such as addresses, hashes,
room codes, durations and amounts.

Cyan owns actions and text links; pink is limited to artist/support provenance;
green is the single live/available state; and status colors describe outcomes.
Track aura remains atmospheric and cannot replace semantic state. The muted
text role was raised to `#a7b8cf` so it remains above 4.5:1 on the brightest
supported measured aura.

Core components now agree on filled play triangles, quiet back navigation,
checkboxes, icon size, live dots, nested account sections and status placement.
Music and Rooms introductions use one readable title group, and the release
rights status appears before the action that depends on it. These are
presentation changes only: playback, payments, room state and publication
semantics are unchanged.

`docs/index.html` was reviewed and left unchanged because the public visual
identity description did not change. Product DevNet generated a ten-item live
catalog snapshot during validation; that unrelated generated diff was
inspected and reverted.
