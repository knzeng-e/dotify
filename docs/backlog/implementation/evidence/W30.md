## Result and decisions

- **Real client identity.** The API keys its rate limit on `Fly-Client-IP` when `API_TRUST_PROXY=fly`. Signaling prefers `Fly-Client-IP`, otherwise the last `X-Forwarded-For` hop, and no longer trusts the client-supplied leftmost hop. Both Fly configs enable the setting. The audit's finding that limits were shared behind the proxy is plausible from the code but was not confirmed against live logs; step 9's read-only check confirms it either way.
- **Signaling fan-out.** The twelve global `rooms:updated` broadcasts are removed. The empty legacy snapshot is still sent once per connection, and `rooms:list` still answers with `[]`, so old clients keep working. Solo presence accepts at most 6 new declarations per socket per 10 s (clearing always allowed) and broadcasts at most one changed aggregate per 2 s.
- **Room codes.** `crypto.randomInt` replaces `Math.random`. The length stays six characters from the same 32-symbol alphabet so existing links, QR codes and the client format checks keep working. A longer code is a W39 or later decision.
- **Room creation.** At most 10 creations per network per minute and 2,000 open rooms. The checks run before the caller leaves its current room, so a refusal never closes that room. Replies carry `RATE_LIMITED` or `ROOMS_BUSY` with a readable `error`; the existing client shows `error`.
- **Catalog and sessions.** The catalog snapshot and a new session revocation file live on the existing contribution volume. A stable `SESSION_EPOCH` (Fly secret) keeps sessions valid across redeploys, which removes the stale host-tip session trap handled by #283. Revoked session IDs are persisted so they stay revoked. An unreadable revocation file forces a random epoch, so everyone signs in again.
- **Key responses** carry `Cache-Control: no-store` for allowed, denied and invalid requests.
- **RPC bounds.** Access reads time out after 4 s with one retry, with an optional `PASEO_ASSET_HUB_RPC_FALLBACK`.
- **Process hygiene.** Both images start Node directly and close on SIGTERM (10 s forced exit). The signaling image runs as `node`. **Deviation:** the API image stays root because the Fly volume at `/data/contributions` is root-owned; switching users would break the contribution ledger and the new catalog path. Node stays at 22.13.1 (unchanged; no upgrade in this slice).

## Compatibility and operations

- New configuration: see "Trusted pilot hardening (W30)" in `docs/operations/deployment-configuration.md`. `SESSION_EPOCH` must be set as a Fly secret by the owner to get session continuity; without it behavior is unchanged.
- Protocol: `room:create` may now fail with `RATE_LIMITED` or `ROOMS_BUSY`; `rooms:updated` is sent only on connection; solo presence updates are coalesced. Documented in `docs/reference/socket-events.md`. No client change is required.
- Migration: none. The first boot with the new catalog path performs one cold reindex; later deploys reuse the snapshot.
- Rollback: redeploy the previous images. Unset `SESSION_EPOCH` only to invalidate sessions.
- Data: the revocation file holds session IDs and expiry times only (no address, token or signature).
