## Result and decisions

The [runnable harness](../../../../research/room-scaling/README.md) proves a
reduced ownership/admission model and actual local SFU forwarding. It does not
implement production horizontal rooms. [ADR 0037](../../../adr/0037-room-scaling-and-sfu.md)
keeps the current single signaling instance and 24-guest cap, compares SFU
alternatives/cost boundaries and lists bounded production follow-ups.

The actual current Dotify server with a Redis Socket.IO adapter still returns
`ROOM_NOT_FOUND` for cross-instance join and for resume after process replacement.
This observed failure is expected: the adapter does not share its application
state. The prototype separately stores room authority and distributes events.
A planned drain transfers authority; an unplanned owner death waits for its lease.
Neither result proves uninterrupted audio during a deploy.

## Measured local verification

One retained complete run, 30 sequential cross-node event samples, 30 concurrent
admission attempts and one 25-subscriber audio room. Raw synthetic counters and
exact versions are in [the JSON artifact](W39-local-2026-10-29.json). Local timings
are not WAN, production p95, unique people or audible first-sound measurements.

| Scenario | Observed result |
| --- | --- |
| Actual server plus adapter: cross-node join / restart resume | Both rejected with `ROOM_NOT_FOUND`, exposing the existing local-state boundary |
| Reduced two-process room: 30 events | p50 1.30 ms, p95 3.05 ms, max 3.76 ms |
| 30 concurrent joins with one existing guest | 23 accepted, 7 refused; shared ceiling remains 24 |
| Wrong host credential / guest publication | Refused |
| Planned drain and resume on the other process | 2.46 ms through first synthetic event; epoch advances, old owner fenced |
| Reusing old resume credential after takeover | Refused after credential rotation |
| SIGKILL of owner with a surviving remote guest | Recovered in 1593.80 ms through first event with a 1.5-second test lease |
| Paused Redis | Mutation returns `STORE_UNAVAILABLE`; no local success fallback |
| Local SFU: one host + 25 guest connections | All 25 receive RTP and decoded samples; exactly one host outbound audio stream |
| Independent SFU participant API | One publisher, 25 subscribe-only guests; guest publish attempt refused |
| Loopback guard / formatting / backlog / whitespace | Pass |

## Compatibility and operations

No production application code, runtime, source file, content key, wallet,
Product permission, hosted setting or paid service changes. Research packages
are separate from app bundles and deployment images. All test network endpoints
are literal loopback addresses. Temporary room credentials are random, expire
and are omitted from retained evidence; temporary config is removed. Child
signaling/SFU processes receive only the minimal test environment. Only the
harness's own randomly named Redis container is removed.

The native SFU terminates ordinary WebRTC encryption; its operator could record
the host stream. No end-to-end media secrecy is claimed. Admission tokens are
local research fixtures, not the implementation of a Dotify SFU join service.
The reduced protocol excludes production SDP/ICE, tip/TURN/artist authorization,
listener crash leases, chat replay, discovery/privacy and shared abuse limits.
Do not deploy it or copy its 60-second room TTL / 1.5-second owner lease into Fly.

Rollback: delete the isolated experiment; deployed room behavior is unchanged.
Physical Product mobile/desktop, independent networks, forced TURN, media
continuity across shutdown and provider/region comparisons remain unrun. The
public project page and deployment runbook state this boundary.
