## Result and decisions

The [pre-implementation decision](../../../adr/0032-streaming-renditions.md)
defines manifest addressing, authenticated objects, a durable nonce ledger and
the compatibility boundary. This first reviewable slice transcodes a synthetic
master into three AAC-LC fMP4 renditions, measures loudness, encrypts the original
archive and every init/media object, and authenticates the complete manifest.
Its browser reader verifies release identity and authentication before exposing
media. It cannot select the archival master for playback.
An authorized holder of the same release key can still decrypt that archive
manually; the reader restriction is not an artist-only key boundary or DRM.

The encoder snapshots caller-owned master bytes, key bytes and release scope
before asynchronous work, and clears its owned clear buffers on completion or
failure. Its child receives only PATH and locale settings, never the API process's
credentials. This limits accidental exposure; it is not an operating-system
sandbox. An activated upload worker still needs filesystem/process isolation.

Existing routes, artist publication, key derivation and running playback are
unchanged. The DAV2 writer gains a defensive low-half counter bound far above
the actual 50 MiB upload budget. No v3 reference is registered or returned by
the production upload endpoint in this slice. There is no new secret or UI flag.

The actual-key fingerprint scopes permanent exclusive prefix reservations;
fsync precedes encryption. The counter's high bit separates v3 nonces from
the reviewed production release-bound DAV2 writer regardless of its random
prefix. Legacy key-v1/full-random-nonce migration is refused. Retries burn their
old generation, never reset a counter, and can reuse unchanged ciphertext
without another AES invocation. Operator loss/rollback of the reservation store
is an explicit custody boundary, not silently repaired by recreating it.

### First-sound model

Two observed samples, one per engine, use the same synthetic 8.2-second WAV,
known authorized key and a deterministic browser route model of 50 ms RTT plus
body transfer at 5 Mb/s. The baseline reads/decrypts original DAV2 WAV into a
Blob; the new path reads/authenticates the manifest, init and first AAC 160
segment. Timing ends at the media `playing` event.

| Engine | Original DAV2 WAV | AAC first segment |
| --- | --- | --- |
| Chromium | 1,625 ms | 361 ms |
| WebKit | 1,545 ms | 451 ms |

These are single-sample, emulated-network measurements with a fixed key, not a
median, live gateway comparison, wallet timing, physical first sound or a
subsecond production guarantee. The dedicated reporter retains the synthetic
JSON measurement. CI generates its own fixture from the same commit and tests
all three engines; its results must be recorded separately.
