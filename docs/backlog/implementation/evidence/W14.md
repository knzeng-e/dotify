## Result and decisions

W14 adds an optional Three.js room galaxy behind the existing
`RoomDiscoveryRenderer` boundary. The default Rooms view remains the 2D
sky/list path, and desktop users can opt into 3D through the renderer switch.
This keeps the release condition honest: the galaxy is available for review and
bounded browser testing, but it is not promoted as the default before real
device performance is measured.

Both the 2D sky and the 3D galaxy now use `roomConstellationPosition(roomId)`,
which places rooms from their identity instead of their list index. A new room
can appear without rearranging every existing room. Labels are limited in dense
views, while selected rooms always keep context.

The 3D canvas is visual only. Room selection and join remain DOM controls over
real `OpenRoom` summaries, so wallet-free guest joining, host-only protected
access, and listener key isolation are unchanged. The renderer falls back to
`SkyOfRooms` for mobile, reduced motion, unavailable WebGL, context loss, and
feature rollback.

Three.js was added directly rather than through a React wrapper. This keeps the
integration small and makes runtime lifecycle, pixel ratio, visibility pause,
and GPU disposal explicit. The normal web and Product builds lazy-load the
`three` chunk; the Bulletin single-file build inlines it by design, and the docs
call out that size tradeoff.
